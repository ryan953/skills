Task Lifecycle

A person enters a task and it is todo. Someone reads it and starts it. Creating a PR moves it into review, and a task can have several PRs. When every linked PR is merged and every subtask is done, the task becomes done by itself. Closed PRs don't count. At any point before done, someone can decompose the task into subtasks: it becomes a parent and keeps its status.

States and transitions

Inside In review: the PR

While a task is in review, each of its PRs runs a machine of its own, seen from the author's side. The PR keeps three facts, and its status is read from them in priority order. That is why fixing CI and addressing every comment lands the PR back on awaiting review, or on accepted if a reviewer already accepted it.
